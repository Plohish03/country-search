# DESIGN

## 1. Отмена устаревших запросов

Каждый запрос получает собственный `AbortController` (`createSearchController`, `src/core/searchController.ts`). При **каждом** изменении ввода (`input()`) активный запрос сразу отменяется через `abort()` — ещё до того, как debounce запустит следующий. Иначе за время ожидания debounce устаревший ответ успел бы прилететь и отрисоваться под уже новым текстом.

`searchCountries` объединяет сигнал отмены с `AbortSignal.timeout()` через `AbortSignal.any()`, поэтому один `fetch` реагирует и на новый ввод, и на таймаут. В `catch` ошибки различаются по `name` (`classifyError`, `src/core/errors.ts`): `AbortError` — наша же отмена, пользователю не показывается; `TimeoutError`, `HttpError` и сетевые ошибки — настоящие, показываются с кнопкой «Повторить». Ответ 404 — не ошибка, а пустой результат.

Почему не просто флаг «актуальный ли ответ»: флаг лишь скрывает последствия — старый запрос продолжает занимать соединение, сервер и трафик, а решение «игнорировать» приходится дублировать во всех местах, которые используют результат. `abort()` останавливает работу в источнике, а Network tab честно показывает отменённые запросы. Дополнительная проверка `request.signal.aborted` после `await` — страховка на случай, если ответ уже был получен в момент отмены.

## 2. Задержка debounce: 300 мс

Константа `DEBOUNCE_DELAY_MS` в `searchController.ts`. Без задержки каждая буква даёт запрос: лишняя нагрузка на API, мигание индикатора загрузки и больше шансов на гонку. Если задержку сильно увеличить (1–2 с), приложение будет казаться «зависшим»: пользователь закончил печатать, а реакции нет. 300 мс — типичный компромисс: короче паузы между буквами при обычном наборе, но ещё незаметная для пользователя.

## 3. Сложность

`mapCountryResponse(raw)`: O(L + C + B), где L — число языков, C — валют, B — границ страны; остальные поля копируются за O(1). Для списка из n стран — O(n · (L + C + B)). Дополнительная память того же порядка. Кэш (бонус) не реализован.

## 4. Принципы чистого кода

- **Единственная ответственность.** Сеть (`searchCountries.ts`), преобразование (`mapCountryResponse.ts`), классификация ошибок (`errors.ts`), координация ввода/отмены (`searchController.ts`) и DOM (`ui/render.ts`) разнесены по файлам.
- **Чистые функции.** `mapCountryResponse` и `classifyError` не зависят от сети и DOM и тестируются без моков.
- **Внедрение зависимостей.** `createSearchController` получает `search` и `onState` параметрами, поэтому в тестах подставляется настоящий `searchCountries` с мокнутым `fetch`, а контроллер не знает про DOM.
- **Нет «магических чисел».** `REQUEST_TIMEOUT_MS`, `DEBOUNCE_DELAY_MS`, `API_URL` — именованные константы.
- **Ранние возвраты.** `searchCountries` (404, `!ok`), `run` и `input` в контроллере не вкладывают условия друг в друга.
- **Явные имена и типы.** `SearchState` — размеченное объединение, поэтому `switch` в `buildState` проверяется компилятором на полноту.
